## 現在の状況
以下のコマンドを実行し、現在のリポジトリの変更とステージング状況を正確に把握してください。

- ステージング済みの差分: !`git diff --cached`
- ワーキングツリーのステータス: !`git status`

## 指示
上記の変更内容を確認した上で、ユーザーのリポジトリに対して以下のステップに則って実行してください。

### 1. セキュリティおよび除外チェック（コミット前）
- 変更されたファイルや未追跡のファイルの中に、`.env` などの環境変数ファイル、APIキー、その他機密情報が含まれていないか必ず確認してください。
- 疑わしいファイルがある場合は、`git check-ignore -v <ファイル名>` を実行して適切に無視されているか確認してください。もし機密ファイルが紛れ込んでいる場合は、処理を中断してユーザーに警告してください。

### 2. ファイルのグループ化とステージング（git add）
- 変更内容（作成・修正）を論理的なグループ（コンポーネントごと、機能ごとなど）に分類してください。
- 分類したグループごとに、`git add <ファイル名>` を実行してステージングエリアに追加してください。

### 3. コマンド引数の確認とコミット（git commit）
- ユーザーがこのコマンドの引数（`$ARGUMENTS`）としてコミットメッセージを指定している場合は、その文字列を最優先でコミットメッセージとして使用してください。
- 引数が空の場合は、ステージングされた変更内容から「簡潔でわかりやすいConventional Commits（例: `feat:`, `fix:`）に準拠したメッセージ」を自動生成してください。
- `git commit -m "<メッセージ>"` を実行してください。

### 4. リモートへの反映（git push）
- コミットが完了したら、現在のブランチを確認し、`git push` を実行してリモートリポジトリに変更を反映してください。
- すべての処理が完了したら、プッシュした内容の要約をユーザーに報告してください。
