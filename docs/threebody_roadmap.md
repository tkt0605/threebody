## 0. 本書の位置づけ

`threebody_dev_phases.md` は I0〜I6 の**体系**を定義している（意図の一生を軸に境界を引き、
各フェーズに反証可能な完了条件を置いた）。ただし次の3つは書かれていない。

1. **どのファイルを触るか** — 完了条件はあるが着手点が無い
2. **完了をどう検証するか** — 「反証可能な形」で書かれているが、検証手順が無い
3. **フェーズに属さないゲート** — `legal.ts` の名義確定は I0〜I6 のどこにも属さないまま残っている

本書はその3つを埋める。**体系そのものは変更しない。** 順序は
`I0 → I1 → I2 → I3 → I4 → I5 → I6` のまま固定する。

### W1 — I0（記録）＋ I1（完結）を1本の作業として（M〜L）

**本書で唯一、体系の作業単位を束ねる箇所。**

#### 3.2 なぜ束ねるか

`threebody_dev_phases.md:328` は「I0 と I1 は衝突しない」と書いているが、実際はもっと強い。
**両者は同じ発火点を触る。**

| 発火点 | I0 が必要とするもの | I1 が触る理由 |
|---|---|---|
| `StopButton.vue` → `cancelGeneration()` | `interrupted: true` の記録 | 停止導線はそのまま |
| `useWakeWord.ts:74`（barge-in 検知） | `interrupted: true` の記録 | I1(a) 選択肢Bで「誤送信の取り消し」に転用する |
| `useVoiceInput.ts:182-214`（`confirming`） | `rephrased` の記録 | I1(a) で**このブロックごと作り替える** |

3行目が決定的で、**I1(a) は `confirming` ブロックを廃止する**（選択肢B）。
I0 を先に実装して `confirming` に記録処理を足すと、その処理は I1 で消える。
逆に I1 を先にやると、廃止したあとの新しい発火点にもう一度記録を足しに戻ることになる。
**どちらの順でも同じ場所を2度書く。** だから1本にする。

#### W1-1 — 記録の器を作る（I0 / S）

```ts
// src/types/intent.ts — 意図的に3フィールドだけ。増やしたくなったら我慢する
export interface TurnSignals {
  interrupted: boolean    // 停止 or バージイン = 「今の答えは要らなかった」
  rephrased: number       // 言い直し回数 = 「うまく言えていない」
  repeatOf?: string       // 同主旨の過去メッセージid = 「前の答えが刺さらなかった」
}
```

- **触るファイル** — `src/types/intent.ts`（新規）／`src/composables/useChat.ts`（`sendMessage` と `persistMessage`）／`docs/schema.sql`
- **やること** — `content_blocks` に載せるか `messages` に列を足すかを決め、スキーマを1回で確定させる
- **やらないこと** — LLM呼び出し、分類器、`IntentRouter`、4個目のフィールド
- **完了判定** — 停止して送り直した会話を Supabase で開き、`interrupted` が立った行が見えること

> **スキーマだけは先に確定させる。** 記録は貯まるのに時間がかかり、途中で形を変えると貯め直しになる。
> 図書館の分類体系は後から作れるが、蔵書は先に集め始めないと増えない。

#### W1-2 — 確認ステップを廃止する（I1(a) / M）

`threebody_dev_phases.md:338` の決定どおり **選択肢B（確認ステップ自体を廃止）** を採る。

- **触るファイル** — `useVoiceInput.ts:182-214`（`confirming` / `confirmText` / `confirmSend` / `redo` / `cancelConfirm`）／`ChatView.vue:307-312`／`VoiceSphereDialog.vue:55-56`／`ChatView.vue:129`（分割代入）
- **やること** — `stop()` で確認状態に入らず直接 `onFinish(text)` を呼ぶ。誤認識の取り消しは既存の barge-in（`useWakeWord.ts:74`）に担わせる
- **やらないこと** — ASR差し替え、ウェイクワード専用エンジン（→ 横断トラック）
- **設計上の注意** — 送信が可逆だからこそ確認を外せる。この判断は I5 の Permission 原則「**可逆なら推測し、不可逆なら訊く**」の先取りであり、**ここで一度決めたら I5 まで一貫させる**
- **残る論点** — バージインは「割り込んだ後に話した内容」しか拾えない（`threebody_dev_phases.md:220-222`）。誤送信の取り消しとして使うなら、割り込み直後に**直前の送信を破棄する**動作が要る。ここは実装時に決める

#### W1-3 — 初回導線の反転（I1(b) / S）

- **触るファイル** — `src/components/EmptyBrainState.vue`（4分岐すべての着地が `:63` の「設定を開く」）
- **やること** — 着地を「まず声で試す」に変える。`not_signed_in` / `limit_reached` / `global_limit_reached` の3分岐は**現在の文言を保つ**（`limit_reached` と `global_limit_reached` の区別は意図的に分けたもの。潰さない）
- **完了判定** — 新規アカウントでログインし、**マウスとキーボードに触らずに**1往復できる

#### W1 全体の完了判定（実行手順）

1. 新規の Google アカウントでログイン
2. マイク許可のダイアログ以外、**画面に一度も触れない**

## 4. 横断トラックの差し込み条件

`threebody_dev_phases.md` は4トラックを定義しているが、**いつ着手するかが未定義**。
本書で条件を決める。

| トラック | 差し込む条件 |
|---|---|
| **基盤負債**（`feedback` の受け側） | **G0 の直後**。告知して人が来る前に。ただし当面は Supabase ダッシュボードを見る運用で塞ぎ、**コードは書かない** |
| **基盤負債**（中断応答の永続化） | **W1 と同時**。中断理由の区別が要る作業で、W1 が中断イベントを扱うため重なる |
| **基盤負債**（Render のプラン確認） | **G0 の直後**。無料プランならコールドスタートで初回50秒。一般ユーザーには致命的 |
| **確信度**（一致度の構造化抽出） | **W3 の直後、W5 より前**。差別化の資産だがボトルネックを外さないため、資金の壁を越えてから。Phase 遅延は1〜2週間で済む |
| **音声基盤**（ASR抽象化） | **W3 以降で随時**。データ主権の矛盾解消は思想上重要だが、どのフェーズの完了条件でもない |
| **アクセシビリティ**（`VoiceSphere` のキーボード操作） | **W1 と同時が望ましい**。W1 が「指を使わない」導線を作る作業なので、「指しか使えない人」の導線も同じ回に見ておくと二度手間にならない |
| **基盤負債**（E2E・i18n・二重保存・モデル名手入力） | **W3 以降**。ユーザーが増えて初めて痛くなる種類 |
