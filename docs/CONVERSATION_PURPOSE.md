# 会話を成果へつなぐ実験

## 今回の解釈

Threebodyの音声会話と既存のLLM接続を使い、会話から何を持ち帰るかを本人が扱えるようにする。目的を毎回の会話へ強制せず、任意の「bodyノート」として追加する。会話画面の常設欄ではなくダイアログにし、発火点はサイドバー（AppAside）とヘッダ（AppHeader）の「bodyノート」に置く。

## 要件と検証仮説（実装前）

1. 目的と完了条件、進捗を編集できる。仮説H1: 会話の長さではなく、望んだ成果に近づいたかを振り返れる。
2. 決定事項・仮説・未決事項・次の一歩を別欄で扱う。仮説H2: AIの提案や推測を、本人の決定と混同しにくくなる。
3. ノートから次の相談文を作り、既存の入力欄へ追加する。本人が修正・破棄・送信でき、生成中は既存の停止操作を使える。仮説H3: 整理した内容を実際のLLM相談につなげられる。
4. 自作のMarkdown / テキストをノートへ読み込める。欄名（目的 / 完了条件 / 決定事項 / 仮説 / 未決事項 / 次の一歩 / 資料）と一致する見出しはその欄へ、それ以外の本文は「資料」へ入る。既に書いてある欄は消さず追記する。

進捗は本人の申告であり、自動の達成判定ではない。ノート操作だけでモデル呼び出しや外部操作をしない。新しい有料サービスは導入しない。

## 境界

ノートはこのタブのメモリに会話ごとに保持する。再読み込みで消えるため、Markdownで持ち出せるようにする。別会話への自動引き継ぎ、長期記憶、PC操作、自動抽出・実行は今回の対象に含めない。ノートは送信前にはAIへ渡らず、音声だけの発話へも自動付与しない。

既存検索機能は `build/search_mcp` の `6ac5776` に保存した。指示どおりmainから分岐したため、この実験へマージしない。

## 手動検証

1. `npm run dev:all` で起動し、ログインしてヘッダ右上のノートアイコン、またはサイドバーの「bodyノート」からダイアログを開く。Esc・背景クリック・×で閉じ、もう一度開けることを確認する。
2. 目的に「Threebodyの次の実験を決める」、完了条件に「1週間で試せる変更と評価方法が決まる」を入力する。
3. 決定事項に「既存LLMを使う」、仮説に「目的が見えると脱線に気づける」、未決事項に「音声中に邪魔にならないか」、次の一歩に「試す場面を3つ挙げる」を入れる。
4. 入力欄に自分の質問を先に書き、「入力欄に追加」を押す。元の質問が残り、決定と仮説が別に記載され、自動送信されないことを確認する。文を修正して送信し、必要なら生成停止する。
5. 進捗を「取り組み中」「完了」と変更し、これは本人が判定する表示であることを確認する。「ダウンロード」でMarkdownを保存して内容を開く。
6. 別会話・新規会話へ切り替えてノートが混ざらないこと、元の会話に戻ると同じタブ内では戻ること、ログアウト後に前ユーザーの内容が残らないことを確認する。再読み込みで消えることも確認する。
7. スマートフォン幅でもダイアログ内部をスクロールでき、閉じると会話領域が戻ることを確認する。
8. 「ファイル添付」で保存したMarkdownを読み戻し、同じ欄に戻ることを確認する。次に見出しの無い自作の `.txt` を読み込み、「資料」に入って相談文にも載ることを確認する。ファイルは512KBまで、各欄は2000文字、資料は65536文字まで。追記後に上限を超える場合は全欄を変更せず案内する。ファイル上限は、日本語を含む最大サイズのノートも保存後に読み戻せるよう設定している。
9. 資料に `## 決定事項`、`進捗: 完了`、コードブロックを含めて保存し、空のノートへ読み戻す。資料が決定事項へ移らず、進捗も勝手に変わらないことを確認する。保存Markdownでは各欄の本文をフェンスで囲んで区別する。旧形式のMarkdownも読み込めるが、すでに旧形式で失われた欄の境界は復元できない。
10. 開発者ツールで通信を遅くし、会話A→Bと素早く移動する。最後に選んだ会話とノートが残り、履歴の取得中は「会話を読み込み中…」が出て送信できないことを確認する。

## 評価方法

H1/H2/H3の体験上の効果は未確認。3回の実会話で、終了時に完了条件を達成したか、仮説を決定と取り違えたか、相談文の修正量と邪魔に感じた場面を記録する。自動テストは状態分離・入力保持・送信制御等の実装上の条件を検証し、利用価値の証明とは区別する。

## 再検証と修正（2026-09-06）

Claude Codeで追加されたダイアログ、ファイル読み込み、新規会話の下書き保持、ヘッダ・サイドバーの入口、設定テンプレートの廃止を維持した。

- Markdown中の見出し・進捗・コードが別欄に解釈される問題を回帰テストで再現し、保存時の本文の囲みと読み込み時のフェンス処理で修正した。
- ファイル読み込み中の会話切り替え、ログアウト、閉じる操作、連続読み込みで、古い結果を追記しないようにした。文字数制限は直接入力と読み込みで共通化し、追記は全欄まとめて検証してから適用する。
- 開く要求がマウント前に届いた場合にも対応し、相談文の追加はダイアログを閉じてから行う。入力欄にフォーカスが戻り、下書きは保持される。
- 会話の非同期取得・作成・保存に世代番号を設けた。古い取得結果で会話画面を戻さず、初回の質問と応答が重なっても会話の作成を一度にまとめる。履歴読み込み中の送信も防ぐ。
