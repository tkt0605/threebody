## 1. 到達点：LLM OS（確定・再検討しない）

中島聡さんの `LLM_OS.md` が示す **Application-centric → Intent-centric** の転換を、「一人の人間が毎日使う OS」として実装する。

```text
ユーザー → 意図を表明 → LLMが理解 → Capabilityを組み合わせる → 必要なUIを生成 → 結果
```

ThreeBody 固有のテーマは、その意図処理を**単一の知性ではなく複数の視点で行い、その過程が見えて聞こえる**こと。

| 層 | 役割 | 現状 |
|---|---|---|
| **Layer 1 — LLM** | 考える | 実装済み（`backend/llm/providers/`：Anthropic / OpenAI / DeepSeek / Ollama） |
| **Layer 2 — Runtime** | 理解・判断・組み合わせ・実行 | **Perspective と Synthesis のみ実装済み。Intent / Capability 以降が未着手** |
| **Layer 3 — Computer** | 世界を動かす | 未着手（**外を触れる**フェーズの MCP が入口） |

**すでに持っている資産**（新規に作る必要が無い）— 視点の定義 `constants/bodyPersonas.ts` / 注入 `useSystemPrompt.ts` → `BodyConfig.personaPrompt` / 並列処理 `llm/textService.ts` の `orchestrateMultiBody()` / 統合 `synthesis_start` → `text` / 可視化 `VoiceSphere.vue` ＋ `useVoiceNarration`。`BodyPersona` は provider と直交しているため**モデルが入れ替わっても ThreeBody は残る**。「三体＝固定の3モデル」ではなく「3つの異なる知性の協調」という抽象化は、コードの事実として既に成立しており、視点の追加は union 型への1行追加で済む。

## 3. フェーズ一覧

境界は「機能が増えたか」ではなく **意図がどこまで到達できるようになったか** で引く。

`操作の記録 → 声だけで話せる → お金の壁を越える → 好みを覚える → 外を触れる → 道具を増やせる → 画像も扱える`

意図は**寿命の異なる4層**に割れ、保存先は寿命で決まる（既存の3テーブルにそのまま乗る。新アーキテクチャは要らない）。

| 意図の層 | 寿命 | 保存先 | 状態 |
|---|---|---|---|
| 話し終わったか | 数百ms | 保存しない | **実装済み** `lib/endpointing.ts` |
| 何をしてほしいか | 1ターン | `messages` | 操作の記録／好みを覚える |
| 今日これを終わらせたい | 会話1本 | `conversations` | 好みを覚える（原始形は `.title`） |
| 短く答えて・日本語で | 生涯 | `user_setting` | 好みを覚える（現在は手動設定のみ） |

| # | フェーズ | 完了条件（反証可能な形） | 状態 |
|---|---|---|---|
| 1 | **操作の記録** | 停止・割り込み・言い直し・再質問が会話に紐づいて残る | 停止・割り込みまで完了 |
| 2 | **声だけで話せる** | マイク許可後、**画面に一度も触れず**に 発話→応答→次の発話 が回る | **中核完了**（残り: 初回導線） |
| 3 | **お金の壁を越える** | 有料プランが1件成立し、全体枠を上げても財布が破綻しない | 未着手 |
| 4 | **好みを覚える** | 設定が1つ以上、**設定画面を開かずに**確定する | 未着手 |
| 5 | **外を触れる** | MCP 1本が動き、**声から起動できる** | 未着手 |
| 6 | **道具を増やせる** | 3種類の呼び出しが同じ入口を通り、不可逆操作だけが確認を要求する | 未着手 |
| 7 | **画像も扱える** | 音声・テキスト以外の入出力が1つ通る | 未着手 |

**順序の根拠** — ①「操作の記録」が先頭なのは追加コストゼロで、貯め始めるのが早いほど価値が出るから。②「声だけで話せる」が課金より前なのは、沈黙と「まず設定しろ」が残ったまま売っても払う理由が立たないから（**売れる状態にしてから売る**）。③ 課金が「外を触れる」より前なのは、**課金は遅らせるほど難しくなり**（後から上限を入れるとサービス劣化に見える）、**道具の共通化は遅らせるほど簡単になる**（実装が増えるほど抽象化の精度が上がる）から。難易度が時間で逆向きに動くので順序が決まる。加えてツール接続は入力トークンを増やし、**無料枠をさらに削る**。④「好みを覚える」が「外を触れる」より前なのは、道具に渡す意図が先に存在する必要があるから。

> **抽象層は設計するものではなく、具体が3つ並んだときに「同じだ」と気づいて括り出すもの。**

### ~~名義の確定~~ ✅ 完了（2026-08-17）

`OPERATOR_NAME` を実名へ確定し ⚠️ コメント2件を削除（値は `constants/legal.ts` が正本。本書には転記しない）。`CONTACT_EMAIL` は実受信を確認できたため据え置き。施行日は告知前で「改定」にあたらないため `2026年8月14日` のまま。表示先は `/terms`（`:21` `:158`）/ `/privacy`（`:23` `:195`）の4箇所。**課金到達時に再確認が要る** — 特定商取引法で氏名に加え住所・電話番号が必要になり、屋号を立てる判断もそのタイミング。

### 操作の記録 ◐ ／ 声だけで話せる ◐

両者は**同じ発火点を触る**ため1本の作業として進める。確認ステップを廃止すると言い直しの検出箇所そのものが変わるので、記録を先に書くと捨てることになる。

- ~~**記録の器**~~ ✅（`152842e` `42aa407`）— `types/intent.ts` の `TurnSignals { interrupted; rephrased; repeatOf? }`、`messages` に `signals` / `modality` 列（`schema.sql` ブロックD、本番適用済み）。**やらないこと**: LLM呼び出し・分類器・4個目のフィールド
- ~~**中断の理由を見分ける／停止を記録する**~~ ✅（`1ab4159` `9201ac3`）— 停止・割り込みだけ保存し、会話切替による中断は保存しない（切り替え先へ誤って書き込むため）。0文字で止めた場合も器だけ残して記録する
- ~~**確認ステップの廃止**~~ ✅（`d217b7d`、実機確認済み）— 『◯◯でいいですか？』を撤去し、無音（`endpointing.ts` が語尾から900〜3000msを判定）でそのまま送信
- **初回導線の反転（S）** — `EmptyBrainState.vue` の4分岐すべての着地（`:63` の「設定を開く」）を「まず声で試す」へ。`limit_reached` と `global_limit_reached` の区別は意図的なもので**潰さない**
- **言い直し・再質問の記録** — `rephrased` は「送信直後に割り込んで言い直した」を発生源に。`repeatOf` は正規化した完全一致のみ（類似度は推論なので使わない）

### 入力の検証（お金の壁の必須前提・S）

`backend/routes/chat.ts` に `messages` の件数・サイズ検証。現状の切り詰めは `useChat.ts:110` の `HISTORY_LIMIT = 10` でフロントのみ、サーバー側は `express.json()` の既定100KBが事実上唯一の壁で意図した防御ではない。**課金より前に置く理由**: 有料ユーザーができた後の上限追加は「サービス劣化」に見える。**完了判定**: 巨大 `messages` の `curl` が 400、回帰テストが `backend/tests/chatRoute.test.ts` にある。

### お金の壁を越える（★分水嶺・L）

設計は既にある: 無料＝三体固定レベル2 / 有料＝上限引き上げ / **BYOK・Ollama＝無制限無料**。**完了判定**: 有料プランが1件成立。

> **この順序が成立しない条件** — 課金がゲートなのは「次の10人がシェアキーの無料ユーザー」である場合のみ。**当面の対象を自分＋BYOK/Ollama ユーザーに絞るなら $0.5/日 の壁は存在せず**、課金を後ろに送って「好みを覚える」→「外を触れる」へ直行してよい。動かす場合は理由を本書に明記すること。

### 好みを覚える（M〜L）

`useChat.ts` の `switchConversation` / `startNewConversation` にフックし、その会話の目的・未解決か・出てきた制約を抽出。**絶対の制約: 抽出をクリティカルパスに置かない**（応答前に挟むと、確認ステップ廃止で消した沈黙が戻る）。**会話を離れるときに1回だけ**。Ollama があればローカルで回し、無ければスキップして **記録が無くても動く**設計にする。**完了判定**: `SettingsDialog` を開かずに設定が1つ確定する（例: 「短く」の反復 → 一度だけ訊いて `useSettings` へ昇格）。

### 外を触れる（MCP 1本・M）

`backend/` に**ベタ書き**。新しいディレクトリを切らない。やらないこと: 共通インターフェース、レジストリ、段取り／権限確認／結果検証の各層。**完了判定**: MCP 1本が**声から**起動する。

> **MCP と Capability は並列ではなく縦の関係。** MCP はプロトコル（どう繋ぐか）、Capability は設計概念（何ができるか）。MCP がカバーするのは実行の一部だけで、**段取り・権限確認・結果検証は提供しない**。繋いでも中身は自分で書く。なお ThreeBody には既に MCP と無関係な capability が動いている（読み上げ・並列思考・永続化）。

### 道具を増やせる（L）

**着手条件**: 呼び出しの**形が3種類**揃うこと。接続本数ではない（MCPサーバー1本が Tool を4個公開することがある。逆に3本繋いでも全部同じ形なら抽象化にならない）。ここで**権限の原則**を実装として確定させる — **可逆な操作は推測して実行し、不可逆な操作は必ず訊く**（`DeleteAccountDialog.vue` の二段確認が先取り）。意図推定に要求される精度は操作の可逆性で決まるため、**記録が完璧でなくても外の世界を安全に開けられる**。

**新しい考えが出たときの手順**

1. **7章と矛盾しないか** — 矛盾するなら、まず**決定を覆すだけの理由**が要る。無ければ書かない
2. **どのフェーズの完了条件を動かすか** — どれも動かさないなら、それは**書かなくてよい考え**。会話で終わらせる
3. **書くなら章を選ぶ** — 3章＝順序・完了条件 / 4〜6章＝着手点・検証手順・差し込み条件 / 7章＝決定と「やらない」判断
4. 分量が増えて読めなくなったら、**新ファイルを作らずに古い記述を削る**

**その他**

- 順序・完了条件を変える → 3章を直し、理由を7章に追記する
- 着手点・検証手順を変える → 4〜6章のみ
- 完了した項目は**消さずにチェックを入れて残す**（順序の判断根拠が辿れなくなるため）
- `docs/` に置いてよい md は本書だけ。`schema.sql` は md ではなく DB の正本なので別枠
