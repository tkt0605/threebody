## 0. 結論

**守り（セキュリティ・コスト）は一般公開水準に達している。攻めの入口（誰が使えるか・法的説明・退会）が未達で、この3件だけが本当のブロッカー。**

| 対象 | 判定 |
|---|---|
| 知人・技術者に配る | **今すぐ問題なし** |
| 一般ユーザーに告知する | **3件を潰してから**（下記1章） |

3件はいずれも機能追加ではなく欠落の穴埋めで、実装1〜2日規模。

## 2. 告知前に潰すべき3件（ブロッカー）

### 2.1 入力手段が音声のみ — 最大の1件

`ChatView.vue` にチャット用の入力欄が1つも存在せず、`useVoiceInput.ts:108` は
SpeechRecognition が無い環境で `'このブラウザは音声認識に対応していません'` を出して**そこで行き止まりになる**。

| ブラウザ | 状況 |
|---|---|
| Chrome | 動く（想定環境） |
| **Firefox** | Web Speech API 非対応 → **何もできない** |
| **iOS Safari** | `recognition.continuous = true`（`useVoiceInput.ts:141`）を実質サポートせず、`onend` での再start頼み。動くが不安定 |
| モバイル全般 | ウェイクワード常時待機はマイク常時オンが現実的でない |

一般ユーザーにとって「音声が使えない」は「壊れている」と同義。
テキスト入力欄1つで、対応ブラウザが一気に全域へ広がる。
棚卸し 1.1（最優先）・2.1、外部レビュー #11 と同根。

### 2.2 利用規約・プライバシーポリシーが存在しない

`LoginView.vue:68` が「続行すると利用規約に同意したものとみなされます」と表示しているが、
**その規約はリポジトリにもサイトにも無い**（`grep -riE "プライバシー|privacy|利用規約|terms" src/ README.md public/` → 該当は当該1行のみ）。

会話内容をSupabaseに保存し、第三者API（Anthropic）へ送信している以上、説明義務がある。
Google OAuth の審査要件でもあるため、流入が増えてから足元をすくわれる類の欠落。

### 2.3 退会（アカウント削除）の導線が無い

会話単位の削除（`useChat.ts` の `deleteConversation`）はあるが、
アカウントと全データを一括削除する手段が無い（`AppAside.vue` に該当UIなし）。
個人情報保護法の「利用停止・消去の請求」に応じる手段として、外部公開サービスには必要。

## 3. ロードマップ（ユーザー数で区切る）

### 3.1 最初に壊れる場所の算数

```
全体枠 50回/日 ÷ 個人枠 3回/日 = 17人/日 でゼロ
```

実際は全員が3回を使い切らないため、**デイリーアクティブ 30〜50人**あたりで
「本日ぶんの無料お試し枠（全体）が終了しました」が常態化する。
ここがスケール上の最初の壁であり、フェーズを切る自然な境界になる。

重要なのは、この上限が**ユーザー数ではなく運営の財布（$0.5/日）から来ている**こと。
ユーザーが増えても上限は自動では動かない。広げる原資は課金からしか出ない。

### 3.2 段階表

| 段階 | 規模の目安 | この段階で壊れるもの | やること |
|---|---|---|---|
| **T0 告知前** | — | ブラウザ・法務・退会 | ① **テキスト入力欄**（Phase 3の前提でもある）<br>② 規約・プライバシーポリシー2ページ + `LoginView` からリンク<br>③ アカウント削除（conversations → messages → content_blocks → user_setting の連鎖削除）<br>④ **`schema.sql` 6章ブロックC の適用確認** — 未適用だと失敗分の全体枠が戻らず、枠が目減りし続ける |
| **T1 〜10人** | 知人・SNS | 「壊れても気づけない」 | ⑤ `feedback` テーブルを**運営が読む手段** — 現状 `useFeedback.ts` は insert のみで、エラー報告が届いても気づけない（棚卸し 2.7）<br>⑥ Renderのプラン確認 — 無料プランならコールドスタートで初回50秒待ち。一般ユーザーには致命的。`render.yaml` は `plan` を意図的に書いていないため、実設定の確認が要る<br>⑦ **確認ステップの音声化** — Phase 2 の残り1件。これでハンズフリーが初めて閉じる<br>⑧ 中断応答の永続化（`useChat.ts:565` の `if (!aborted)`。リロードで消える） |
| **T2 〜50人/日** | **全体枠が枯れる** | 無料枠モデルそのもの | ⑨ **Phase 4 定額課金を前倒し** — 「無料=三体Lv2固定 / 有料=上限引き上げ / BYOK・Ollama=無制限無料」の三層は設計済み<br>⑩ 残り回数の常時表示（今は `EmptyBrainState` でしか見えない）<br>⑪ **サーバー側の入力検証** — `messages` の件数・サイズを見ておらず、切り詰め（`useChat.ts:110` の `HISTORY_LIMIT = 10`）はフロントだけ。現状は `express.json()` の既定100KBが事実上の唯一の壁で、これは意図した防御ではない。運営負担の共有キー経路があるため、有料化前に必ず入れる |
| **T3 〜500人** | 品質と多様性 | 「動くが荒い」が可視化 | ⑫ E2E（Playwright）とブラウザ互換の検証 — 現状ゼロ。Vueコンポーネントのテストも0件（棚卸し 1.9 / 2.11）<br>⑬ i18n — `Language` 型は7言語あるがUIは日本語ハードコード（棚卸し 1.11）<br>⑭ レート制限のストア共有化 — 今はメモリ。複数インスタンス・再起動でリセットされる<br>⑮ `messages.content` と `content_blocks` の二重保存の解消（棚卸し 3.10）<br>⑯ モデル名の自由入力をリスト化 — `SettingsDialog.vue:330` がテキスト入力のため、タイプミスがそのままAPIエラーになる（棚卸し 1.12） |
| **T4 それ以降** | 定着後 | 差別化 | ⑰ **一致度の構造化抽出** — 3モデルの不一致は「確信度が低い」というシグナルそのものだが、`llm/textService.ts` は文字列連結して捨てている。ここがこのプロダクト固有の価値の源（外部レビュー #8、中心軸2）<br>⑱ ASR抽象レイヤ — データ主権の理念と「ChromeではGoogleへ送信」の矛盾を解く<br>⑲ Phase 5 MCP / Phase 6 マルチモーダル |

### 3.3 順序の理由

- **①テキスト入力を最上段に置いた** — Phase 3（初回体験）の前提であると同時に、「使えるブラウザが増える」＝流入の分母そのものを変える唯一の項目だから
- **⑨課金をT2に前倒しした** — ロードマップ上の Phase 4 より先に現実の壁（3.1の算数）が来るため。全体枠を広げる原資は課金からしか出ない
- **⑪入力検証を課金より前に置いた** — 有料ユーザーができた後に上限を入れると「サービス劣化」に見えるため
